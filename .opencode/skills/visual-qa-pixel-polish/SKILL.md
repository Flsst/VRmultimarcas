# Visual QA & Pixel Polish

Assume another developer built the page. Review it critically before accepting it.

## Inspect the whole page

Check:
- hero composition;
- section-to-section rhythm;
- container alignment;
- vertical spacing;
- typography hierarchy;
- line breaks;
- visual density;
- color consistency;
- border/radius consistency;
- image quality and crop;
- CTA prominence;
- footer finish.

## Detect AI-template symptoms

Flag and fix:
- repetitive cards;
- identical three-column sections;
- excessive pills;
- unnecessary gradients;
- generic glow effects;
- rounded containers everywhere;
- too many centered sections;
- decorative blobs;
- meaningless statistics;
- repeated copy patterns;
- mismatched icon styles.

## Pixel-level issues

Look for:
- 1–8px alignment errors;
- inconsistent gaps;
- baselines that do not align;
- unintended borders;
- clipped shadows;
- overflow;
- text too close to edges;
- uneven card heights when alignment matters;
- buttons with inconsistent heights;
- images with wrong object position;
- accidental duplicated assets.

## Responsive polish

Review mobile separately. Never assume desktop fixes translate.

Check:
- headline wrapping;
- hero subject visibility;
- CTA order;
- navigation;
- section padding;
- content density;
- fixed/sticky overlap;
- image crop;
- horizontal scrolling.

## Refine

Do not stop at reporting issues if you are allowed to edit. Fix them, then re-check the affected viewport.

The target is deliberate visual quality, not mere technical correctness.
